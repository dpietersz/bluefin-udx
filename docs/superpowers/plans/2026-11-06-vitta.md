# Vitta Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a signed `ghcr.io/dpietersz/vitta:testing` image on Universal Blue's desktop-less base that runs the full niri desktop + dotfiles on the T580, with a retro Gruvbox greetd/Quickshell login screen and matching hyprlock lock screen that follow a day/night rule.

**Architecture:** New BlueBuild recipe `recipes/vitta.yml` (`FROM ghcr.io/ublue-os/base-main:44`) reusing `recipes/common.yml` plus Vitta-only modules. One palette (`/usr/share/vitta/theme/palette.toml`) and one CLI (`vitta-theme`) decide colours and light/dark for both the greeter (Quickshell in `cage`, via greetd) and the lock screen (hyprlock, configured in `~/dotfiles`). CI builds a `vitta` leg next to the existing ones and pushes only `:testing`.

**Tech Stack:** BlueBuild (rpm-ostree, files, script, systemd, akmods, brew, os-release modules), Fedora 44 RPMs (greetd 0.10, cage 0.3, quickshell 0.2.1), Python 3.14 stdlib (`tomllib`, `zoneinfo`), QML (Quickshell `Quickshell.Services.Greetd`), hyprlock, chezmoi templates, GitHub Actions + podman + cosign.

**Spec:** `docs/superpowers/specs/2026-11-06-vitta-design.md`

## Global Constraints

- Base image `ghcr.io/ublue-os/base-main`, `image-version: 44`. Image name `vitta`; os-release `ID=vitta`, `NAME="Vitta"`, `VARIANT_ID=vitta`, `IMAGE_ID=vitta`.
- No Flatpak, no AppImage delivery. No `gdm`, `gnome-shell`, `gnome-session*`, `zfs`, `incus`, `cockpit*`, `uupd`, `sysstat`, `setroubleshoot*`, non-x86 `qemu-system-*`/`qemu-user-static*` in the image.
- Stripes outer→inner, ~5 px each, outer radius ~14 px. Dark: `#689d6a` `#ebdbb2` `#d65d0e` `#cc241d` on `#282828`. Light: `#427b58` `#3c3836` `#af3a03` `#9d0006` on `#fbf1c7`. Stripe 2 = theme foreground.
- Font family string `Monaspace Neon`, from `https://github.com/githubnext/monaspace/releases/download/v1.400/monaspace-static-v1.400.zip`, sha256 `ab66d71be751495f679727332a3345597943bd4d7beebca03f5cde04bf994de7`, only `Static Fonts/Monaspace Neon/*.otf` (42 files) into `/usr/share/fonts/monaspace-neon/`.
- Day/night: `light` iff local time is between sunrise and sunset at `/etc/vitta/theme.conf` coordinates; default Amsterdam `52.37`, `4.90`. Only greeter + lock screen use it.
- greetd greeter user is `greetd` (Fedora package default). Session command is `niri-session`. Only niri is offered.
- `bluefin-udx` and `bluefin-udx-nvidia` recipes and their CI behaviour stay unchanged. Everything Vitta-only lives under `files/vitta/` (applied only by `recipes/vitta-modules.yml`), never under the shared `files/system/`.
- CI pushes Vitta only as `vitta:testing`, `vitta:<YYYYMMDD>`, `vitta:<sha7>`, signed with the existing `SIGNING_SECRET`; never `:stable`.
- Smoke-test shell blocks inside `podman run ... -c '...'` use only double quotes (existing rule in `build.yml`).

## Review Focus

- Greeter runs before any user session: timezone must come from `/etc/localtime`, not a user env → Task 2 test runs `mode` under an explicit `TZ` and a fixed `--at`.
- Locations with no sunrise/sunset (polar day/night) or a broken `theme.conf` must still yield a mode, never a crash → Task 2 tests.
- `vitta-theme` missing or failing at greeter/lock time must fall back to **dark**, never a blank or unthemed screen → Task 6 preview test and Task 9 lock script test.
- Wrong password, multi-prompt PAM conversations and greetd errors must show a red message in the card and return to the password field; the greeter must never hang → Task 6 preview scenarios.
- Non-Vitta machines (P14s on `bluefin-udx-nvidia`) must keep today's install skips, expected-image check and hyprlock unchanged → Task 8 and Task 9 template tests.
